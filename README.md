# 个人题库刷题网站

一个本地可跑的题库刷题网站：把 TXT 题库导入成结构化数据，支持刷题、判分、错题集、收藏、搜索与统计。

同时它是我的**软件测试实践项目** —— 75 条测试用例设计 + 37 条 pytest 自动化测试，都围绕它展开。

## 功能

- **题库管理**：上传 TXT 文件解析入库，支持 8 个题库 / 685 道题
- **五种题型**：单选、多选、判断、填空、简答
- **刷题**：答题即时判分；选项随机打乱（防止靠位置记答案）
- **错题集**：自动收集答错的题，支持重练
- **收藏**：标记重点题目
- **搜索**：按题干关键词检索
- **统计**：答题正确率、各题库进度
- **导出**：把题库导出成 docx

## 技术栈

Python · Flask · Flask-SQLAlchemy · SQLite · Jinja2 · Chart.js · pytest · Gunicorn

## 测试（本项目的重点）

围绕它建立了一套自动化质量保障流程：

| 项 | 内容 |
|---|---|
| 测试用例 | **75 条**，覆盖题库上传、四种题型判分、错题集、收藏、搜索、统计与导出，含边界值与异常路径 |
| 自动化测试 | **37 条 pytest**，通过 Flask `test_client` 做进程内接口测试 |
| 数据隔离 | 会话级数据库备份还原，**保证测试不污染真实数据** |
| 缺陷发现 | 通过自动化测试定位并修复 **2 个缺陷**：① 选项未按设计打乱（实现与设计文档不一致）② 删除带收藏记录的题库触发 ORM 完整性错误、返回 500 |
| 回归 | 修复后 37 条全部通过 |

## 本地运行

```bash
make install   # 建虚拟环境 + 安装依赖
make test      # 跑 37 条 pytest
make run       # 本地启动
```

## 部署

`deploy.sh` 一键部署到云服务器：虚拟环境隔离 · Gunicorn + systemd 服务托管与开机自启 · 防火墙端口放行。

## 目录结构

```
app.py          Flask 主应用与路由
models.py       数据模型（题库 / 题目 / 答题记录 / 收藏）
parser.py       TXT 题库解析与答案判定
rebuild_db.py   从「标准题库/」重建数据库
tests/          pytest 测试
标准题库/        原始 TXT 题库
templates/      页面模板
static/         样式与脚本
deploy.sh       部署脚本
Makefile        常用命令封装
```

## 说明

- 数据库文件（`quiz.db`）**不纳入版本管理** —— 它可以从「标准题库/」重新导入生成。
- 代码为 **AI 辅助开发 + 自主调试与部署**。
